What is gRPC Streaming?

Unlike REST (1 request → 1 response), gRPC allows continuous data flow over one connection.

| Type             | Direction   | Real Assessment Use Case      |
| ---------------- | ----------- | ----------------------------- |
| Unary            | 1 → 1       | Submit exam (you already did) |
| Server Streaming | 1 → Many    | Live evaluation updates       |
| Client Streaming | Many → 1    | Upload answers batch          |
| Bidirectional    | Many ↔ Many | Real-time AI proctoring       |

We’ll implement Server Streaming first (most common in real systems).

When You Should Use Streaming

Use it when:

✔ Processing takes time
✔ You need progress feedback
✔ You want high-throughput pipelines
✔ Large payload chunking
✔ AI / analytics workloads

Do NOT use streaming for simple CRUD.

VERY IMPORTANT (Avoid Circular Call Loop)

If:

Exam.API → calls Result.API
Result.API → calls Exam.API
Exam.API → calls Result.API again

You will create:

Infinite recursion
Stack overflow
Timeout

In real enterprise systems we avoid this by:

Clear service ownership

No circular dependencies

Using Orchestrator pattern if needed


Enterprise Best Practice

Instead of bidirectional circular calls means :

We usually use:

API → Service A → Service B → Service C

NOT:

A ↔ B ↔ A means parent to child again child to parent in a same call
