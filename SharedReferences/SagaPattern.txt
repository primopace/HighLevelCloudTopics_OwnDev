6️⃣ Message Acknowledgment (Important Detail)

Consumer must acknowledge message:

ACK

Example flow:

Queue
-----
msg1
msg2
msg3

Consumer receives msg1.

If processing succeeds:

ACK

RabbitMQ removes msg1 from queue.

Then consumer receives msg2.

If processing fails:

NACK

RabbitMQ may:

Retry message
Requeue message
Send to dead-letter queue

What Happens If Consumer Crashes

Example:

msg1 delivered
consumer crashed

RabbitMQ detects no ACK and:

msg1 returned to queue

Another consumer will process it.

This guarantees message reliability.

Event Versioning is mainly used when your event schema changes over time, especially in systems using Event Sourcing or distributed microservices. It helps you evolve events without breaking old data or consumers.

Since you are building CQRS + Event Sourcing + Saga, event versioning becomes very important.

1️⃣ The Core Problem Event Versioning Solves

In Event Sourcing, events are stored forever.

Example stored events:

OrderCreatedEvent v1
OrderCreatedEvent v1
OrderCreatedEvent v1

After 1 year you change the event:

OrderCreatedEvent v2

Now your event store contains:

OrderCreatedEvent v1
OrderCreatedEvent v2

Your system must still read the old events.

Without versioning:

❌ Event deserialization fails
❌ Replay breaks
❌ Read models break

Event versioning solves this.
