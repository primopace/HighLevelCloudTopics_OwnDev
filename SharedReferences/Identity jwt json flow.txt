 1️⃣ Why you don’t see the public key inside the JWT

This is by design.

A JWT never contains the public key.

What you’re seeing is correct:

JWT Header
{
  "alg": "RS256",
  "kid": "7A6767E69AEB1991295D83B8F8A382F7",
  "typ": "at+jwt"
}

JWT Payload
{
  "iss": "https://localhost:7021",
  "aud": "assessment_api",
  "scope": [ "assessment.read", ... ],
  "role": "Admin",
  ...
}


❌ No public key
❌ No private key

✔ Only a key identifier (kid)

2️⃣ Where is the public key then?

👉 Published by IdentityServer via JWKS endpoint

IdentityServer exposes public keys here:

https://localhost:7021/.well-known/openid-configuration


Inside that response you’ll see:

"jwks_uri": "https://localhost:7021/.well-known/openid-configuration/jwks"


Open it directly 👇

https://localhost:7021/.well-known/openid-configuration/jwks

    }
  ]
}


🟢 THIS is the public key

4️⃣ Does IdentityServer need the public key to generate token?

❌ NO

IdentityServer uses:

Private key → sign token

Public key → publish for validation

Analogy:

🔑 Private key → lock (sign)

🔓 Public key → unlock (verify)

IdentityServer never uses the public key to generate tokens.

1. In the Code (The standard way)
Most developers hardcode the algorithm (e.g., RS256) in the application configuration. Since the algorithm is a "technical spec" rather than a "secret," there is no security risk in having it in your source code. The code tells the library: "Use this specific math to sign the token."
2. In Key Vault (The "Best Practice" way)
Experienced developers often store the Algorithm Name in Key Vault alongside the key (usually as a Tag or a Secret).
Why do they do this?
Key Rotation: If you decide to move from RSA (RS256) to Elliptic Curve (ES256) for better performance, you can update the Key and the Algorithm Name in Key Vault.
No Redeploy: Your application picks up the new algorithm automatically without you having to change a single line of code or restart/redeploy the server.
How it looks in practice:
Option A: Simple (Hardcoded)
csharp
// The algorithm is fixed in the code
var signingCredentials = new SigningCredentials(keyFromVault, SecurityAlgorithms.RsaSha256);
Use code with caution.

Option B: Flexible (From Key Vault)
csharp
// 1. Get the key from Vault
var key = await keyClient.GetKeyAsync("MySigningKey");

// 2. Get the algorithm name from a Tag you saved on that key
string alg = key.Value.Properties.Tags["AllowedAlgorithm"]; // e.g., "RS256"

// 3. Use them together
var signingCredentials = new SigningCredentials(keyFromVault, alg);
