
Azure BlobStorage
===============
The URL like:

https://storageaccount.blob.core.windows.net

is automatically created by Azure when you create a Storage Account in Azure Blob Storage inside Microsoft Azure.
You do not manually create this URL.

Below is the complete process.

1️) Create a Storage Account in Azure
Login to Azure Portal
Click Create Resource
Search Storage Account
Click Create

Fill basic details:
| Field                | Example            |
| -------------------- | ------------------ |
| Subscription         | Your subscription  |
| Resource Group       | `rg-demo`          |
| Storage Account Name | `billingstorage01` |
| Region               | Central India      |
| Performance          | Standard           |
| Redundancy           | LRS                |

Click Review + Create → Create

2️) Azure Automatically Creates the Endpoint

After deployment, Azure automatically creates the Blob endpoint:

https://billingstorage01.blob.core.windows.net

Structure:

https://{storage-account-name}.blob.core.windows.net
Example:
| Storage Account  | Endpoint                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------ |
| billingstorage01 | [https://billingstorage01.blob.core.windows.net] 
| erpdocuments     | [https://erpdocuments.blob.core.windows.net]       |


3️) Create a Blob Container

Inside the storage account:

Go to Data Storage → Containers
Click + Container

Example:

| Container Name | billing-pdfs |
| Public Access | Private |

Now the container URL becomes:

https://billingstorage01.blob.core.windows.net/billing-pdfs

4️) Upload a File (Example)

If a file invoice.pdf is uploaded:

https://billingstorage01.blob.core.windows.net/billing-pdfs/invoice.pdf

But this won't be publicly accessible unless permissions allow it.

5️) Where to Find the Endpoint in Azure

Open your storage account → Endpoints section.

You will see:
| Service       | URL                                                                                             
| ------------- | -------------------------------------------------- |
| Blob service  | [https://billingstorage01.blob.core.windows.net]   |
| Queue service | [https://billingstorage01.queue.core.windows.net] |
| Table service | [https://billingstorage01.table.core.windows.net]|
| File service  | [https://billingstorage01.file.core.windows.net]  |

6️) Connection String (For SDK)

In Azure Portal:

Storage Account
   ↓
Access Keys
   ↓
Connection String

Example:

DefaultEndpointsProtocol=https;
AccountName=billingstorage01;           --->using this directly access without identity token
AccountKey=xxxxxxxx;
EndpointSuffix=core.windows.net

Your SDK converts this into the endpoint:

https://billingstorage01.blob.core.windows.net

7️) Using Endpoint with Managed Identity (Best Practice)

Instead of connection string:

var client = new BlobServiceClient(
    new Uri("https://billingstorage01.blob.core.windows.net"),
    new DefaultAzureCredential());

8️) Final URL Structure
https://{storage-account}.blob.core.windows.net/{container}/{file}

Example:

https://billingstorage01.blob.core.windows.net/billing-pdfs/abc123.pdf

9️) Enterprise Architecture (Recommended)
User
  ↓
API
  ↓
Azure Blob Storage SDK
  ↓
https://storageaccount.blob.core.windows.net
  ↓
Container
  ↓
Blob File

Azure KeyVault
===================


Yes — to access Azure Key Vault using DefaultAzureCredential() you must use Azure AD authentication (now called Microsoft Entra ID).
But you do NOT need to purchase Azure AD separately. It is included with every Azure subscription.

You only pay for:

Azure Key Vault
Certificate storage / operations

Azure AD itself is free for this use case.

1️) What You Need

Minimum components:
| Component                            | Purpose                         |
| ------------------------------------ | ------------------------------- |
| Azure Subscription                   | Required for all Azure services |
| Azure Key Vault                      | Store certificate               |
| Microsoft Entra ID                   | Authentication                  |
| Service Principal / Managed Identity | Allow API to access Key Vault   |

Azure keyvault more detail
==========================
1️⃣ Why IdentityServer Uses a Signing Certificate

When IdentityServer issues a JWT token, it must digitally sign the token so APIs can verify it.

Example JWT:

Header.Payload.Signature

The Signature is created using a private key from a certificate.

Flow:

Client
   ↓
IdentityServer
   ↓
Token created
   ↓
Token signed with private key
   ↓
Client receives JWT

APIs validate the token using the public key.

2️⃣ Problem With Local Certificates

If you store certificates like this:

certs/identityserver.pfx

Problems:

Secret stored in server
Hard to rotate
Devs may access it
Multiple servers must sync
3️⃣ Enterprise Solution: Azure Key Vault

Store the certificate in:

Azure Key Vault

Then IdentityServer loads it securely.

IdentityServer
     ↓
Azure AD authentication
     ↓
Key Vault
     ↓
Retrieve signing certificate
4️⃣ Typical Architecture
Client
   ↓
IdentityServer
   ↓
Get signing certificate
   ↓
Azure Key Vault
   ↓
JWT signed
   ↓
API
5️⃣ Example: Storing Certificate in Key Vault

In Azure:

Key Vault
   Certificates
      identityserver-signing-cert
6️⃣ .NET Code Example

Install package:

Azure.Security.KeyVault.Certificates
Azure.Identity

Code:

using Azure.Identity;
using Azure.Security.KeyVault.Certificates;

var client = new CertificateClient(
    new Uri("https://myvault.vault.azure.net/"),
    new DefaultAzureCredential());

KeyVaultCertificateWithPolicy cert =
    await client.GetCertificateAsync("identityserver-signing-cert");

Then convert to X509Certificate2.

7️⃣ Add Signing Credential in IdentityServer
builder.Services.AddIdentityServer()
    .AddSigningCredential(certificate);

Now IdentityServer signs tokens using Key Vault certificate.

8️⃣ Extra Security Benefit

Key Vault provides:

automatic certificate rotation
audit logs

HSM backed keys

Supported by:

Azure App Service

Azure Virtual Machines
9️⃣ Even More Secure Option (Large Enterprises)

Instead of downloading the certificate, IdentityServer can sign tokens directly using Key Vault keys.

IdentityServer
     ↓
Key Vault crypto API
     ↓
Sign JWT

Private key never leaves Key Vault.
